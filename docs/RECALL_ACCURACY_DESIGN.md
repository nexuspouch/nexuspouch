# 召回准确性设计（Recall Accuracy）

> 状态：设计稿 v0.1（2026-08-02）
> 定位：保证 `session_recall` / `store_search` 语义召回的准确性——这是
> "统一会话管理"卖点的生死线。核心观点：**先立评估闭环，再谈优化**。

## 0. 结论摘要

- 准确性 = **评估闭环（基准 + 反馈）+ 混合检索 + 过滤与重排 + 会话特有策略
  + 可追溯展示**；
- 第一步是评估集与指标（Recall@K / MRR / nDCG），否则优化无法验证；
- 本地优先约束下，性价比最高的手段是元数据过滤 + 两阶段召回（rerank），
  而不是堆大模型；
- 会话场景特有问题：时间衰减、代码/术语弱点、片段化、去重聚合。

## 1. 评估闭环（根基，R1）

### 1.1 检索评估集（retrieval eval set）

- 从 sessions 空间采样真实会话，构造 `{query, gold_session, gold_message, gold_snippet}`
  对；LLM 辅助生成候选 + 人工校验，首批 100-200 条；
- 覆盖类型：语义问题（"上次部署报错怎么解决的"）、精确术语（变量名/报错串/
  commit hash）、跨 agent、跨项目、时间相关（"上周讨论过"）；
- 存放：`docs/storage_fixtures/recall_eval.json`（共享、可回归）。

### 1.2 离线指标

- Recall@K、MRR、nDCG；
- 命令：`nexuspouch recall eval`（跑评估集输出指标，可对比不同配置）；
- 每次改动（embedding/分块/rerank/权重）必须跑回归。

### 1.3 在线反馈闭环（R3）

- 打开/采纳结果 → 正样本；"结果不对" → 负样本；记入事件流/审计；
- 定期回流评估与调参；可选 A/B（不同 embedding/rerank 配置）。

## 2. 召回管道质量（分层，按性价比排序）

| 手段 | 解决什么 | 状态 |
|------|---------|------|
| 混合检索（FTS5 + 向量 RRF） | 语义 vs 精确术语互补 | ✅ 已落地（hybrid） |
| 元数据过滤（agent/project/date/space） | 缩小候选空间 | 待实现（R1 参数化） |
| 两阶段召回：粗召回 top-50 → rerank top-10 | 精排提升准确率最有效 | 待实现（R2） |
| query 理解/改写（口语化、中英混合、拼写容错） | 用户 query 不精确 | 待评估（R2 后） |
| embedding 模型升级 | 语义更强但资源涨 | 本地优先约束下收益有限 |

### 2.1 rerank 本地方案（R2）

- v1 规则重排：时间衰减 + 关键词命中加权 + 向量相似度加权；
- 可选轻量交叉编码器小模型；
- 远程 LLM rerank：用户显式开启（隐私原因，默认关）。

### 2.2 分块质量

- 按消息 / 语义段落分块 + 重叠，避免切断语义；
- **工具调用结果进索引**（报错常在 tool 输出里，query 是"报错"时要能召回）；
- 敏感信息清洗不破坏可检索性（脱敏词保留类别占位）。

## 3. 会话场景特有策略

1. **时间衰减**：默认近期会话权重高（可调）；支持按时间范围过滤；
2. **代码/术语弱点**：向量对变量名/报错串/commit hash 召回差——FTS5 精确
   匹配兜底是硬需求；
3. **对话片段化检索**：以"消息 + 上下文窗口（前后 N 条）"为单位召回，
   返回片段而非单行；
4. **跨会话去重聚合**：同一问题多会话讨论过——聚合去重，标注
   "最早解决 / 最近讨论 / 多次出现"；
5. **可追溯展示**：结果带会话 URI、时间、agent、snippet 高亮；agent 回答
   引用 `store://` URI，可点击验证（引用纪律已设计）。

## 4. 里程碑（R 系列）

| 阶段 | 内容 | 预估 |
|------|------|------|
| R1 | 评估集 + `recall eval` + Recall@K/MRR/nDCG + 召回参数化（top_k/filter/权重） | 1 周 |
| R2 | 两阶段召回（粗召回 + 规则/小模型 rerank）+ 时间衰减 + 去重聚合 + 片段返回 | 1 周 |
| R3 | 反馈闭环（点击/采纳/纠错事件）+ 定期回归 + 可选 A/B | 1 周 |

## 5. 与现有能力的关系

- 混合检索基线已就位（H 向量搜索 P1 + I 会话 P2 `session_recall`）；
- R1 评估集放共享 fixture，双端与 CI 可回归；
- 参数化查询经 `session_recall` / `store_search` 透出（top_k、filter、权重）；
- 反馈事件走现有 EventBus / 审计链路。

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| 评估集偏差（自标注自嗨） | 人工校验 + 覆盖类型表 + 上线后反馈校准 |
| 本地模型限制准确率 | 混合检索 + 规则 rerank + 可选远程 rerank（显式开启） |
| 反馈数据稀疏 | 先离线评估集兜底，反馈逐步积累 |
| 参数难调 | 配置化 + A/B + eval 回归数字说话 |
